CARCA CLONE v2.0.2 — 学習CPUがミープルを置かない問題の修正

原因
v2.0.1までは、少量の対局記録から作った学習モデルの候補評価だけで配置・ミープルを選んでいました。
「置かない」の評価が高いと、得点を取れる局面でもミープルを配置しない偏りが出ていました。

修正
・学習CPUにも通常の強いCPUと同じ、残りタイル・完成確率・得点・ミープル在庫・拘束リスクの評価を使用。
・タイル配置とミープル判断の両方を修正。ミープルを使える配置も探します。
・学習モデルは評価の近い選択肢を選ぶ好みとして加えます。候補ごとの補正は最大±0.35点に制限。
・無理にミープルを使い切る処理ではありません。在庫がない場合や、温存の評価が高い場合は置きません。
・学習形式は従来通り。読み込み済みのshouldモデルも再学習せず使えます。
・既存の盤面タップ回転と、対局開始時だけ相手を選ぶ表示を維持。

更新手順
1. ZIPを展開。
2. GitHubの0123porupoponnu/carca-cloneで Add file → Upload files を開きます。
3. 中身を同じ階層へアップロードして同名ファイルを上書きし、Commitします。
   ZIPそのものや、フォルダで一段深くなった状態ではアップロードしないでください。
4. 少なくともindex.html、rules.js、cpu.js、strong.js、learning.jsをまとめて更新します。
5. GitHub Pages反映後に再読み込みし、画面上部のv2.0.2を確認します。
6. 新しい対局で「学習CPU」と既存のshouldを選びます。JSONの再読み込みは不要です。

保存キー・学習モデル形式は変更していません。同じURLとブラウザで使う既存データを引き継ぎます。
GitHubへの反映は未実施です。

検証
・自動テスト44件合格。
・「置かない」に極端に偏ったモデルでも、完成都市での得点・回収と序盤の都市投資を確認。
・在庫0のときには配置しないことと、評価処理が盤面・在庫・モデルを変更しないことを確認。
・実際のshould JSONで序盤の都市・道路・修道院への配置を確認。
・ブラウザでの3サイズ完走の結果はVERIFICATION.txtを参照。
・勝率やshould本人の再現度の評価はしていません。iOS Safari実機は未確認です。
