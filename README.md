# CARCA CLONE v2.0.0 — 第2段階の初期版

基本セット72枚、2人対戦、通常CPU（標準／強い）、名前別の学習CPUをまとめた版です。既存のタイル画像・地形定義・得点ルールを引き継いでいます。

## 今回の更新

### 通常CPU「強い」

「相手」で「通常CPUと対戦」、「CPUの強さ」で「強い」を選択。青が自分、オレンジがCPUです。「標準」も残しています。

強いCPUは全ての合法なタイル配置と、その配置での合法なミープル選択（置かない選択も含む）を評価します。

- 基本セットの枚数から、盤面・除外済み・現在の手札を引き、残りの種類と数量を把握します。山札の並び順を参照しません。
- 現在の得点、終了時の未完成地形・草原、完成の見込み、ミープルの残数と回収見込みを評価します。
- 空きマスの全ての隣接条件を、残りの全タイル・全回転と照合します。
- 合うタイルが存在しない／全て出切った場合は、その穴を埋められないと判定します。
- 複数の穴に同じ残り1枚が必要な場合など、物理的な枚数不足も検出します。
- 相手の都市や道路を回収不能にする手も、相手の得点・ミープル効率を落とす選択として評価します。必ず妨害するのではなく、自分の得点との兼ね合いで選びます。

確率は有限の残り枚数から、今後自分が適合するタイルを少なくとも1枚引く確率を計算しています。ただし、複数の穴の確率は近似して組み合わせています。未来の全盤面を読み切る探索や、最善手・勝率の保証ではありません。端末によっては思考に時間がかかります。

### 学習CPU

1. この版で自分が8手以上操作する。1対局分あると始めやすいです。
2. 「記録・学習」→「学習データ」を開く。
3. 名前と自分の色を指定し、「対戦記録を学習用に保存」。CPU対戦では自分の青だけを保存します。
4. 「この人の記録でCPUを学習する」を押す。
5. 「相手」を「学習CPUと対戦」に変更し、学習した人を選ぶ。

新しい版では、配置・回転・ミープルに加え、その局面で比較した候補の特徴も記録します。配置とミープル選択を別々のモデルで学習します。学習は端末内で行い、追加のサーバーや有料APIは使いません。

旧版の名前別記録・URLメモは保持します。旧記録には局面の比較情報がないため、その記録だけからこの学習モデルは作れません。v2で保存した、比較可能な手が8手以上必要です。未確定の手やCPU自身の手は学習対象にしません。取り消して選び直した手は、再保存時に置き換えます。

3対局以上の記録があれば、1対局を学習から外して評価します。それ未満では、保存した記録内の候補一致率を表示し、未知の対局での再現度は未検証と明記します。候補を絞った範囲での一致率です。同じ特徴を持つ候補は区別できないため、本人の完全な再現や、記録が増えるほど必ず強くなることは保証しません。記録が不足する種類の判断は通常CPUの標準評価で補います。

名前別にモデルと記録をJSONで書き出し・読み込みできます。追加・修正した記録を保存すると、その人のモデルは再学習が必要になります。BGAのURLはメモ保存のみで、自動棋譜取得はまだ実装していません。

## 更新方法

今回必要なアプリファイルは次の5つです。新しいファイルの入れ忘れに注意してください。

- `index.html`
- `rules.js`
- `cpu.js`
- `strong.js`（新規）
- `learning.js`（新規）

ZIPを展開し、GitHub `0123porupoponnu/carca-clone` の Add file → Upload files で上記を上書き／追加してコミットしてください。フォルダの中身をリポジトリ直下に置きます。Pagesの公開完了後、同じURLを再読込し、見出し「第2段階 v2.0.0」を確認します。GitHubへのpush・マージは今回行っていません。

保存キーはv1と同じです。v1の学習データ・途中対局はそのまま読み込みます。更新前に学習JSONを書き出すとバックアップになります。途中の対局を続ける場合は「新しい対局」を押さず、同じURLを再読込してください。

## 遊び方と得点

タイルを90度単位で回し、緑の＋に配置します。そのタイルだけにミープルを最大1個置くか、「ミープルを置かずに次へ」。同じ連結地形が占有されていると置けません。別々の地形を合流させる相乗りは可能です。

開始アンダーバー1枚＋山札71枚、合計72枚。紋章違いを分けて24種類です。

- 都市：完成はタイル＋紋章につき各2点、未完成は各1点。
- 道路：タイル1枚につき1点。交差点で分かれ、ループも完成。
- 修道院：自分と周囲8マス。完成9点、終了時は存在する分。
- 草原：終了時のみ、接する完成都市1つにつき3点。同じ都市は草原ごとに1回。農夫は途中回収されません。
- 最多ミープルのプレイヤーが満額。同数なら双方が満額。
- 同じ地形が同じタイルに何度入っても、タイルは1回だけ数えます。

盤面は1本指で移動・2本指で拡大縮小。取り消しはその画面を開いてからの履歴の範囲です。CPU対戦ではCPUの応答も含めて自分の操作まで戻ります。再読込前の取り消し履歴は保持しません。2人対戦は同じ端末を交互に使う方式です。オンライン対戦、川・修道院長などの拡張は対象外です。

最終得点は対局中の得点・未完成都市・未完成道路・未完成修道院・草原・合計の6行に集約します。

## 起動・検証

GitHub Pagesを推奨します。iOSの「ファイル」アプリのプレビューではなく、SafariでPagesを開いてください。

```sh
python3 -m http.server 8000
# 別ターミナル
node --test tests/rules.test.cjs
```

ブラウザ内の自動テスト（通常のデータとは別のQA保存キーを使用）：

- 2人対戦: `http://localhost:8000/tests/browser-qa.html`
- 強いCPU: `http://localhost:8000/tests/browser-qa.html?cpu=1`
- 記録→学習→読み込み→学習CPU: `http://localhost:8000/tests/browser-qa.html?learned=1`

Playwrightの外部クリック試験も同梱しています。

```sh
npm install
npx playwright install chromium
npm run test:browser
```

実施結果と限界は `VERIFICATION.txt` を参照してください。実機Safariと実際のピンチ操作は未確認です。
